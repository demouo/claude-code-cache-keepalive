# Cost math: 10 warm pings vs. one cold start

This compares what the keepalive **costs** (10 pings, each a cache **read** of the
prompt prefix) against what one **cold start** costs (one cache **write** that
re-processes the whole prefix after the cache expired).

Generated by [`cost-table.py`](cost-table.py) from Anthropic's public pricing
page (`platform.claude.com/docs/en/about-claude/pricing`, USD per 1M tokens).

## Assumptions

| Item | Rate |
| --- | --- |
| Cache read (keepalive ping) | **0.10×** base input — 0.025× on Fable 5.1 / Mythos 5.1 |
| 5m cache write | 1.25× base input |
| 1h cache write (what a cold start costs on a 1h TTL) | 2.00× base input |

* "Context" = the cached prefix size in tokens.
* The ping also emits a few output tokens; that is negligible next to the prefix and is excluded.
* Subscription plans are not billed per token; there the same ratio describes how much more compute/plan-usage a cold start burns versus a cache read.

## Why the default cap keeps it net-positive

At the defaults (`CCKA_IDLE_SECONDS=3000`, `CCKA_MAX_IDLE_SECONDS=43200`) one idle
stretch pings at most ~14 times (12 h ÷ 50 min) before pinging stops. That is
below the **20-ping** break-even for a 1 h write, so with the defaults the
keepalive stays cheaper than letting the cache go cold — and it stops there
instead of pinging an abandoned session forever.
